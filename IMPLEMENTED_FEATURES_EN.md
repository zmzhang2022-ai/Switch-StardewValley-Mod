# Stardew Valley Switch Native Mod: Implemented Features

Last updated: 2026-08-24  
Current version: v9 Preserves Jar + Geode Crusher Performance  

## 1. Target Game Version

```text
Game: Stardew Valley
Version: 1.6.15.3
Title ID: 0100E65002BB8000
Game Build ID: A5C617C14A7F3F6620B3BC8136965A4822D32B9C
```

All function offsets, virtual-function slots, and ABI findings apply only to the
Build ID above. They must be re-analyzed after any game update or Build ID
change and must not be reused directly.

## 2. Injection and Deployment Architecture

The current implementation uses:

```text
Atmosphère
  + exlaunch/subsdk runtime injection
  + ARM64 function hooking
  + native C++ Automate Lite
```

The original `exefs/main` is not permanently modified. The Mod is injected as
`subsdk9` and uses a `main.npdm` overlay containing the additional required SVC
permissions.

Deployment layout:

```text
atmosphere/
└─ contents/
   └─ 0100E65002BB8000/
      └─ exefs/
         ├─ subsdk9
         └─ main.npdm
```

## 3. Automate Lite Networks

The following connection layouts are supported:

```text
[Chest]—[Machine]
[Chest]—[Wood Path]—[Machine]
[Chest]—[Machine]—[Machine]
[Chest]—[Wood Path]—[Machine]—[Machine]
```

Connection and grouping rules:

- Chests, machines, Fish Ponds, and Wood Paths are indexed as automation entities.
- Entities occupying the same tile participate in the same flood fill.
- Entities connect in the four cardinal directions; diagonal connections are not used.
- A machine can connect onward to another machine.
- One network may contain multiple chests and multiple machines.
- Each Automate tick collects finished products before attempting another input cycle.
- If all chests are full, the machine is not emptied and its product remains in place.
- Transactions are not simulated by directly writing timers, `heldObject`, or inventory stacks.

Important original game interfaces:

```text
Chest.AddItem(...)
Object.AttemptAutoLoad(IInventory, Farmer)
Object/Machine original output lifecycle
```

The original game machine data determines valid inputs, recipes, quantities,
and fuel requirements.

## 5. Wood Path Connector

Wood Paths act as Automate network connectors.

Identification chain:

```text
GameLocation.terrainFeatures raw field
  → NetVector2Dictionary +0x210/+0x218 virtual unwrap
  → TerrainFeature*
  → is Flooring
  → Flooring.GetData()
  → FloorsAndPathsData.ItemId
  → "405" or "(O)405"
```

The concrete dictionary values in `terrainFeatures` are network-field wrappers
similar to `NetRef<TerrainFeature>` and cannot be used directly as
`TerrainFeature*`. The current implementation reproduces the original game's
virtual-function unwrapping flow.

Every Wood Path tile becomes an independent connector node and joins chests and
machines through same-tile and four-directional flood connections.

## 6. Fish Ponds

Fish Ponds are implemented as output-only Automate machines:

- Fish Pond buildings are detected automatically.
- The complete Fish Pond tile area is added to the automation index.
- Products already generated by the pond are read automatically.
- Roe and other products are moved into connected chests automatically.
- Products remain in the pond when all connected chests are full.
- Both direct adjacency and Wood Path connections are supported.
- Fish and quest items are not inserted into ponds automatically.

## 7. Full-Map and Interior Updates

Automate is not limited to the area around the player.

Coverage includes:

- The player's current location.
- All loaded root maps in `Game1.locations`.
- Instantiated building interiors, including Farmhouses and Cabins.
- Cross-map automatic input and output while the player is elsewhere.

The Mod does not force-load an unloaded location solely for automation.

## 8. Performance Scheduling

The old implementation scanned every map in one main-thread frame every 30
ticks, causing periodic stutter. Starting with v8, scheduling is:

```text
Current map: scan every 30 ticks
Background maps: poll one non-current Location every 4 ticks
```

Performance improvements include:

- Full-map work is distributed across frames while preserving complete coverage.
- Background state stores only root/interior indices and does not retain managed `GameLocation*` raw pointers across ticks.
- The terrain-unwrapping virtual function is resolved once per map instead of once per feature.
- Flood-tile deduplication uses open-addressing hashing instead of linear `std::find`, giving expected O(1) lookup.
- The Skull Cavern Elevator keeps a 30-tick interval but is offset by 15 ticks from the current-map Automate scan.
- Long heartbeat logging runs about once every 1,800 ticks and avoids Automate scan frames.

The v8 periodic-stutter fix has been confirmed successfully on real Switch
hardware.

## 9. Skull Cavern Elevator

The current implementation includes:

- An elevator in the Skull Cavern entrance lobby.
- An elevator icon at the corresponding map position.
- Elevator generation on eligible Skull Cavern floors.
- Floor support beyond level 120.
- One elevator stop every five floors.
- A native scrollable menu for deep-floor selection.
- The selectable range is based on the deepest floor recorded by the game save.
- Coexistence with Automate in the same `subsdk9` module.

## 10. Four Ring Slots

The current implementation includes:

- The two original ring slots are preserved.
- Two additional ring slots are added.
- Four ring slots are available in total.
- Layout 2 is used.
- Ring slots do not overlap the hat, shirt, pants, boots, or combat-pet areas.
- Ring insertion, removal, drawing, hover behavior, and effect synchronization are supported.
- The feature coexists with Automate, Fish Ponds, and the Skull Cavern Elevator.
